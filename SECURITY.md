# Security policy

## Supported versions

Only the latest published beta receives security fixes.

## Reporting a vulnerability

Do not open a public issue for suspected vulnerabilities. Report them privately through the GitHub repository's security advisory feature. Include the affected version, a minimal reproduction, and the potential impact.

## Consumer responsibilities

- Create credentialed clients only in trusted server code.
- Never expose bearer or internal service tokens through browser bundles or public runtime configuration.
- Use HTTPS for non-local production APIs.
- Upgrade promptly when a security release is published.
